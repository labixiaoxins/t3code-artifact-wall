本次更新的是 GitHub 源码。当前已安装的桌面应用和公开下载仍为 [C29](https://github.com/labixiaoxins/xiaoxin-t3code/releases/tag/xiaoxin-c29-20261030)，其官方基线是 0.1.5。本次源码同步没有替换已安装应用，也没有发布新的 C30 桌面安装包。

## 为什么先修复历史，再合并更新

此前 GitHub 显示“落后 412 个提交”，其中 286 条来自提交祖先关系缺失造成的账面差距，另外 126 条是尚未合入的官方提交。C29 的实际运行源码已包含官方 0.1.5，但公开分支的提交历史没有完整表达这一关系。

历史桥接提交 `75f0e9b097` 保持 C29 文件树不变，只补回已实际包含的稳定版祖先关系。桥接后，GitHub 比较显示仍有 126 个官方提交尚未合入。随后以冻结的官方主线 `97e35bcf23e4dcf34c2dcffadd37c08db0e01e52` 为目标，对这 126 个提交执行实际合并，逐处处理核心与界面的冲突，并保留双方语义。

历史桥接不是把未合入的主线标成已同步；本次也不是用 `ours` 策略把官方主线挂成父提交却丢弃其代码。正式同步提交保留社区分支与冻结官方主线的两个父提交。126 是提交数量，不是新功能数量；它同时包含功能、修复、测试和内部调整。

## 本次源码带来的主要变化

### 停止任务与恢复行为

- 接入官方 Stop 状态流转和无响应时的 Force stop 入口，保留权限、能力检查及过期 `runId` 保护，避免旧操作误停新任务。
- 合入重启续接、停止后重试、待处理队列释放等相关修复，并保留定制的递归子任务停止约束及用量保护。
- 保留 C29 的压缩拒绝状态修复；另外修复时间线过滤过宽的问题，使“返回后压缩”等场景仍显示明确的压缩状态，同时避免重复显示普通执行提示。

### 数据库与性能相关实现

- SQLite 从单个 reader 调整为最多四个惰性 WAL reader worker，事务继续绑定其取得的 reader；保留 reader 启动失败时的回退逻辑。
- SQL migration 073 为活跃 turn items 新增两个部分索引，不修改聊天正文或删除历史记录。首次建索引仍可能消耗时间、空间及写锁。
- 合入定向恢复读取、后台查询、准备任务分配、Git 状态探测和大 checkpoint 传输等改进。大 checkpoint 的总文件数与完整 diff 入口同时保留，不能把首批文件前缀当作全部文件。
- `temp_store = MEMORY` 减少部分磁盘等待，也可能增加大型查询的内存峰值。上游提交标题中的加速倍数不作为本分支的性能承诺。

### 密钥引用支持与安全修复

- 合入 Secrets 后端能力、密钥提供方契约及环境变量的 `string | SecretReference` 支持。服务端能力已具备，但网页 Secrets UI 的功能开关默认仍为关闭；本次没有启用外部密钥库、导入凭据或读取真实 1Password 内容。
- 合入克隆失败 URL 查询凭据隐藏、签名资源路径日志保护、复合/下划线凭据键脱敏、配对权限与验证码处理，以及会话整理工具拒绝未知参数等安全修复。
- 临时 V1 导入副本采用更保守的清理规则：只自动清理带已退出 PID 的匹配临时目录；存活 PID 和无 PID 的 legacy 目录保留。旧式目录不能仅凭名称证明已无用途，代价是部分旧残留不会自动释放空间。

## 保留的 Xiaoxin 定制

C29 的中文设置与中文搜索、三行输入框、上下文/用量/磁盘入口、图片修改意见开关、图片对比规则、预览小窗锚点及侧栏分组继续保留。新加入的应用自有界面文案同步补齐中文；用户内容、密钥引用、命令、品牌及未知外部诊断保持原样。

官方文件目录栏的宽度与键盘操作改进，不等同于或替代定制预览小窗的锚点修复。官方在本范围曾加入、随后撤回输入框 Markdown 切换按钮，本次保留最终净结果，不恢复已撤回的中间实现。

## CI 工作流的保留

GitHub 当前登录缺少修改 Actions 工作流所需的 `workflow` 权限，因此本次保留社区分支已有的 `.github/workflows/` 配置，未发布官方新增或修改的工作流。应用源码和上游祖先关系正常合并；“落后 0 条”表达提交祖先关系，不表示定制分支与官方每个文件完全相同。没有为这次同步扩大账号权限。
