# C13 → C23: what actually changed

[简体中文](C13-TO-C23.md) · [Home](../../README.en.md) · [Download C23](https://github.com/labixiaoxins/t3code-artifact-wall/releases/tag/xiaoxin-c23-20261028)

The previous public release was **C13, based on official 0.1.1**. C23 uses the **complete official 0.1.3 baseline** and accumulates changes to the core, search, quota safeguards, run visibility, storage operations and everyday UI. It is substantially more than a shorter composer or new sidebar icons.

![C13 to C23 overview](../../assets/community/c23/08-c13-to-c23.png)

## 1. The core crosses two official baselines

C13 used `fe27e8e3dc12dcbb108e9a28fd9b8cb65f34ae92` (0.1.1). The full upstream baseline in C23 is `d2c440312e5f39d59827ed466838a623516454d6` (0.1.3), integrated during C20 and retained afterwards.

Examples relevant to daily work include PDF search across line breaks, handling unreachable environments during search/refresh, recovering subsequent messages after a worktree disappears, compacting superseded process snapshots, background-compaction state handling, history-discovery coordination, MCP schema cleanup, and applicable Claude tool/session and Codex exit-recovery fixes.

These are included implementations. They do not prove that every provider or OS was tested, nor imply fixed quota or performance savings.

## 2. Search beyond a remembered task title

C13 already had Chinese names, full pinyin and initial matching; those are retained features, not new claims. The later addition is the local Spotlight search service, index and result-location integration.

Its worker reads local conversation data and uses a separate rebuildable index cache. Searching does not require sending chats to a model. Result information connects to the command palette and conversation location. Spotlight here is an **application service name**, not a claim of integrating or controlling macOS-wide Spotlight.

## 3. A safeguard beyond showing quota percentages

C13 displayed quota. The later optional Claude subscription safeguard participates in new-message, prepared-work and queued-work admission when enabled for the corresponding provider configuration.

It distinguishes normal, warning, wrap-up and unknown quota states and coordinates work sharing an account. Stale/unavailable readings are not treated as unlimited capacity. Notices and queue handling are not force-killing active processes, and do not guarantee that platform quota information is always accurate. The safeguard is optional, not enabled for every installation by this release.

## 4. Requested and actually reported execution are distinct

The run inspector separates reported and requested models and shows reasoning options, account alias, quota-check time and subtask status. Missing information stays unreported; stale or unreadable quota has an explicit state. It does not invent actual execution from the requested configuration.

Subtasks expand in batches rather than placing all run information permanently above the composer. This supplements the earlier active-work overview.

## 5. Storage gains an execution and recovery path

The added storage service joins inspection, exact-scope plans, archiving, verification, eligible source release and recovery records. Indexes and tiny receipts are not treated as complete rollback backups. Unknown references, unique work and uncertain activity remain protected.

These are product capabilities. The maintainer’s earlier manual Feishu-cache cleanup, personal history migration and observed disk headroom are **not bundled automatic actions or promised space savings**. Each recipient must inspect their own objects and recovery conditions.

## 6. UI refinements are the final layer

Project grouping, artifacts, video, conversation continuity and quota display already existed in C13. C23 retains them while giving titles room through icons, removing repeated model-source rows, softening heavy text, and settling on the 3.5-line composer with a light A1 footer.

Manual resizing was tried internally and then removed. The download represents the final C23 state; users do not need to install intermediate builds.

## Internal stages versus public releases

- **C13:** previous public project workbench and showcase.
- **C16 stage:** search, quota safeguards and run-inspector integration.
- **C17–C19 stages:** actionable storage, applicable backend fixes, model-picker and sidebar improvements.
- **C20:** complete official 0.1.3 integration.
- **C21–C23:** input height and footer refinements from actual feedback.

This is an internal iteration map, **not ten independently published major releases**. Follow the [backup/recovery guide](README.en.md) when upgrading from C13. Replacing the app does not itself prove database downgrade compatibility.

## Evidence basis

The comparison uses C13 commit `b7dee7a38546ac341a73c7f528bec6f415f22c0a` and C23 implementation `6d3627c85508ab2bb45c7f1bf04b07f170d00e2b`. `SpotlightSearch`, `ClaudeUsageProtection`, `RunInspector` and `StorageManagement`, for example, are integrated in C23 and absent from C13. Features already described by C13’s FEATURES document are listed as retained.

Validation scope and current knip issues remain documented in the [README](../../README.en.md). This follow-up changes documentation and illustrations only, not the C23 application binary or implementation identity.
