# 社区改造版：产物墙与「待我处理」工作流

[English](README.md)

基于 [pingdotgg/t3code](https://github.com/pingdotgg/t3code) 的非官方、独立维护的 fork，与上游一样使用 MIT 许可，与 T3 Tools 无隶属或背书关系。

基线：官方 nightly `0.0.46-nightly.20261006.2752`（提交 `d8d037eae`）。改动在 `community/artifact-wall-2752` 分支上，是基线之上的几个小提交，方便审查。较早的 `community/artifact-wall-main` 基于官方 `9bd1d8009`，不含防休眠。

## 为什么做

官方 T3 Code 是很好的 Agent 控制界面，侧栏和会话页以**对话**为中心，写代码很合适。但如果你同时推进很多项目，又混着做图片、网页、文档这类视觉和内容工作，一天里会反复遇到三个问题，翻聊天记录都不好回答：

1. **现在有什么在等我？**
2. **Agent 到底产出了什么，在哪里？**
3. **我从哪个成果继续改？**

这个 fork 做了一条连贯的小流程：_找到等我的会话 → 进入 → 看产出 → 从成果继续_。

## 总览

![侧栏的待我处理、展开的父会话及其三个子任务、右侧产物面板](images/artifact-filtered-light-1280.png)

- **待我处理**：只有一行，因为只有一件事真正在等人。第二行写明原因「子任务 · 待授权」。
- **父会话 `⑂ 3`**：三个子任务收在父会话下，展开时缩进显示，各自保留状态（蓝点＝需要我，绿色「有新结果」，无标记＝已完成）。
- **右侧「产物」面板**：本会话产出的所有文件，按天分组，可筛选（全部 / 图片），并能在「本会话」和「本项目」之间切换。

## 功能

### 1. 待我处理：把所有等人的事放在一处

![子任务正在等待授权，待我处理直接指向它](images/inbox-permission-light-1280.png)

- 跨项目汇总待授权、待回答、有新结果、运行失败，侧栏一个入口，分组有角标，`⌘⇧I` 跳到下一个。
- 子任务的**待授权、待回答**仍会提醒你，显示父会话标题和「子任务 · 待授权」，点击直接进入该子任务（如图，有「Subagent of …」标记，右侧 Lineage 里能看到父会话）。
- 子任务的**有新结果、运行失败**不进入待我处理，因为这些由父会话的模型消化，对你只是噪音。

### 2. 子任务收纳

![父会话折叠为「⑂ 3」](images/sidebar-collapsed-light-1280.png)

- 子任务不再作为侧栏里的独立行；父会话行显示 `⑂ N`，点击展开或收起。
- 父会话不在当前列表（已删除或不可见）时，子任务按原分组显示，不会消失。
- 归档父会话时，同时归档其**空闲**子任务；运行中的会被跳过并明确提示，不会静默失败。取消归档父会话**不会**自动恢复子任务，需在 `⑂` 菜单里点「恢复子任务」。
- ⌘K 搜索仍能搜到子任务。

### 3. 产物墙

![产物面板：缩略图、文件名、时间、大小，以及本会话与本项目范围](images/artifact-filtered-light-1280.png)

- 按会话或项目集中显示**生成的图片、渲染的页面、会话写入的文件和附件**，含缩略图、文件名、时间、大小、筛选与按天分组。
- 支持图片预览、并排对比，以及**把产物重新附加到输入框**继续提修改要求。这些交互在代码和测试里已有，但**截图里没有展示**。
- 只是「被提到」的文件（例如命令输出里出现的旧文件路径）不收，除非修改时间晚于会话创建时间（容差 5 分钟）。附件、渲染的 HTML 和文件改动不受此限。避免墙上堆满旧文件。

官方基线没有集中显示会话或项目产出文件的面板，图片和文件只在聊天记录里。

### 4. 一键新对话，并显示工作目录

![⌥ 点击的选择菜单：最近使用优先，较早的日期目录收进子菜单](images/alt-menu-light-1280.png)

![输入框上方显示新会话将在哪个目录运行，可点「更换」](images/new-thread-workspace-light-1280.png)

- 分类上的「新建会话」直接在记住的默认目录里新建（该分类上次用的目录；没有记录时用最近有活动的成员）。
- `⌥` 点击弹出精简菜单：最近使用优先、`~/` 缩写路径，`~/Documents/Codex/YYYY-MM-DD/...` 这类日期目录收进「更早的历史目录（N）」。
- 发出第一条消息前，输入框上方显示「在 ~/… 中运行 · 更换」，避免在错误目录里开始。

### 5. 侧栏分组与历史扫描

- 模型（Codex / Claude / …）→ 业务分类 → 会话，两层可折叠；顶部近期项目；已归档入口；同步历史按钮。
- `AgentSessionScanner` 扫描全部时间范围（含已归档），有内存预算，并保留原生会话身份。

### 6. 任务运行时保持唤醒（macOS）

- 设置：**Settings → General → Behavior → Keep awake while working**，三个选项：**Mac and screen**（默认）、**Mac only**、**Off**。
- 只要有任务在准备、启动或运行中，服务端就持有 `caffeinate`；全部结束立即释放。只在等授权或输入、或排队中的任务**不算**，所以一个会话挂着等你一夜，不会让 Mac 整晚不睡。
- 绑定服务端进程（`caffeinate -w <pid>`），服务端崩溃或被强杀时不会残留。超过 24 小时的运行记录会被忽略。
- 在服务端实现，所以窗口关着、或无界面的 Mac 主机上也有效；其他平台行为不变。
- 没接外接显示器的笔记本合盖后仍会休眠，这是 macOS 的限制。

## 需要你按自己习惯修改的默认值

- 分类名和目录规则都在一个文件：[`apps/web/src/workspaceCollections.ts`](../../apps/web/src/workspaceCollections.ts)。默认假设 `~/Documents/<分类>` 目录（自媒体、公司管理、交易等），请换成你自己的结构。设置 `workspaceCollections: false` 可回到官方原有分组。
- 自动化会话标题过滤：`apps/web/src/sidebarProviderGrouping.ts` 的 `isAutomationThread`。
- 日期目录归类假设 Codex 的 `~/Documents/Codex/YYYY-MM-DD/<名称>` 临时目录布局。

## 构建

需要 Node `^24.13.1` 和 pnpm `11.10.0`，与官方一致。

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
```

## 验证范围与限制

- 已验证：类型检查；在基线上跑通 web 全部测试和服务端全部测试；在虚构数据沙盒里做过手动检查，覆盖浅色、深色，1280 和 1024 宽度。防休眠还对打包后的 App 做过端到端检查（启动、切换模式、释放、随服务端退出）。
- 已知的官方问题，与本 fork 无关：在维护者环境里，干净官方代码也有 6 项服务端测试失败（入口符号链接、安装归属、Antigravity 路径），有没有本 fork 结果相同。
- 维护者在 macOS 上日常使用了几天，**没有长期稳定性数据**；没测 Windows、Linux、大量产物文件、远程访问和多设备。
- 手机 App 未改动；云登录和通行密钥没有用本 fork 测试。
- 维护者自用的桌面打包脚本不在本分支里，请自行从源码构建或打包。

## 与官方版并行使用

不要让两个不同的构建同时使用同一个数据目录。如果你把本 fork 打成应用，请用独立的名称和数据目录。

## 回馈官方

官方要求新功能先讨论。想让官方吸收其中某项，先开 Ideas Discussion；产物墙和子任务收纳最独立。

社区里已有相关项目（例如跨项目 Agent 看板、独立 Inbox 客户端）。「待我处理」是共同需求，并非这个 fork 独有；本 fork 着重的是上面这条**以产物为中心的闭环**。
